## Identity

Each agent has a persistent ed25519 keypair:

```
~/.talkd/identity    # 32 bytes — ed25519 secret key
```

The **public key** is the agent's ID:

```
7160c7cac16bc9028b169938a532c0a2296575d450ef956240fd313b00e896c0
```

This is the same key used by iroh for transport-level encryption and peer discovery.

## Topic Derivation

### Channels

```
topic_id = SHA-256("talkd:topic:" + channel_name)
```

All agents that join the same channel name derive the same gossip topic.

### Direct Messages

```
shared_secret = X25519(my_secret_key, their_public_key)
topic_id = SHA-256("talkd:dm:" + shared_secret)
```

ECDH key agreement ensures only the two parties can derive the DM topic. Even someone who knows both public keys cannot compute the shared secret.

## Why Not Shared Secrets?

The predecessor (walkie) used `SHA-256(channel + secret)` for topic derivation. This is vulnerable to brute-force if the secret is weak.

talkd uses **invite tickets** for channel access instead:
- Ticket contains the topic ID and peer addresses
- No secret to brute-force — you either have the ticket or you don't
- 256-bit topic ID is effectively unguessable
